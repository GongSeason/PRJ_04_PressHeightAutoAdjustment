## P0-1 引入累计补偿量追踪，统一自动/手动下发语义

**问题**：`MainViewModel.SendPlcCommandsAsync` 写 `手动基准 + 本次自动Δ`，而 `ManualAdjustAsync` 只写 `手动Δ`。自动Δ 每次基于当前窗口偏差重新计算、不累计，后一次写入会覆盖（等于撤销）前一次调整，系统无法收敛。

**设计决策**：手动和自动共用同一个 `CompensationTracker`（方案 A），PLC 永远收到 `tracker.Accumulated`。不设软件侧累计上限，由 PLC 侧卡限制。

**修改**：

1. 新建 `CrimpHeight.Core/Controller/CompensationTracker.cs`（每个压头一个实例）：
   ```csharp
   public class CompensationTracker
   {
       public double Accumulated { get; private set; }   // 当前累计补偿 (mm)

       /// 叠加增量并返回实际叠加值，更新累计值
       public double Apply(double delta)
       {
           Accumulated += delta;
           return delta;
       }

       public void Reset(double value = 0) => Accumulated = value;
   }
   ```
2. `MainViewModel` 持有 `_headACompensation` / `_headBCompensation` 两个 tracker：
   - **自动下发**：`tracker.Apply(autoDelta)` → `SendAdjustmentAsync(head, tracker.Accumulated)`。PLC 永远收到**累计绝对补偿值**。
   - **手动写入**（`ManualAdjustAsync`）：`tracker.Apply(manualDelta)` → `SendAdjustmentAsync(head, tracker.Accumulated)`。删除原有「手动基准 + 自动Δ」的叠加逻辑。`HeadAManualDelta`/`HeadBManualDelta` 仅作为输入框暂存值，写入成功后清零。
   - **写入失败时回滚**：`tracker.Reset(previousValue)`。
3. 删除 `SendPlcCommandsAsync` 中 `HeadAManualDelta + headAAutoDelta` 的叠加逻辑。
4. 累计值持久化到 `compensation_state.json`（仿照 `StopStateService` 的落盘方式），应用重启后恢复，避免重启后累计值归零而 PLC 寄存器仍保留旧补偿。
5. UI：补偿值图表（`AppendCompensationPoint`）改为绘制 `tracker.Accumulated`（实际下发值），不再绘制理论候选值；状态区新增「当前累计补偿」显示。

**验收**：
- 连续两次自动调整后，PLC 收到的值单调累计（如 0.010 → 0.015），不会回退覆盖。
- 手动调整也经过 tracker，与自动调整共享累计值。
- 应用重启后累计值从 json 恢复。

## P0-2 调整后按时间戳 bypass 旧数据 + warmup 冷却

**问题**：自动下发后不重置分析窗口。窗口（150 条）中仍是调整前数据，且 `_issuedPlcCommandKeys` 在每个新数据时间戳即被清空，每来一条新 CSV 记录就可能重复下发，造成过调/振荡。

**设计决策**：不使用固定样本数冷却，而是**按写入 PLC 时的数据时间戳 bypass 旧数据**。调整后只取该时间戳之后的新数据，新数据量满足 `MinSamplesPerEpoch`（50 条）后恢复计算判定。手动调整后也执行同样的 bypass 逻辑。

**修改**（`MainViewModel`）：

1. `MainViewModel` 为每个压头记录 `_headAAdjustDataTimestamp` / `_headBAdjustDataTimestamp`（最近一次成功下发时对应的数据时间戳，使用数据自身时间轴，不用上位机时间）。
2. 自动下发成功后：
   - 调用对应 `_headXArbiter.Reset()` 清空漂移历史；
   - 记录当前 `_dataProvider.LastDataTimestamp` 作为该压头的调整时间戳。
3. 手动写入成功后：同样记录调整时间戳（与自动下发一致的 bypass 逻辑）。
4. 每次刷新时，对每个压头**只取调整时间戳之后的数据**送入 `ArbitrateSingle`。新数据不足 `MinSamplesPerEpoch`（50 条）时自然落入 WarmUp 不动作，等价于冷却期。
5. **删除** `_issuedPlcCommandKeys` / `PreparePlcCommandVersion` 机制（按值去重已无意义，时间戳 bypass 取代其职责）。
6. `ResetAndRefreshAsync` 重置两个压头的调整时间戳，但**不清零** `CompensationTracker` 累计值。

**验收**：
- 模拟 CSV 回放：注入持续偏高 0.05mm 的数据 → 首次调整后，在新样本数达到 50 条之前不再产生第二次下发。
- 两个压头的冷却期互不影响（A 调整不阻塞 B）。
- 手动调整后同样 bypass 旧数据，等待 warmup。

## P0-3 TargetMidpoint 改为可配置（新增）

**问题**：`ControllerConfig.TargetMidpoint` 当前是计算属性 `(UpperLimit + LowerLimit) / 2.0`，不支持目标值不在规格中点的场景。settings.json 中配置的 `TargetMidpoint` 值被忽略（无 setter）。

**修改**：
1. `ControllerConfig.TargetMidpoint` 从计算属性改为可读写属性，默认值为 0（表示未配置）。
2. `Validate()` 中：若 `TargetMidpoint` 为 0 或未配置，自动设为 `(UpperLimit + LowerLimit) / 2.0`；否则校验 `TargetMidpoint` 在 `[LowerLimit, UpperLimit]` 范围内。
3. settings.json 中的 `TargetMidpoint: 12.2` 配置生效。

**验收**：
- 配置 `TargetMidpoint: 12.18`（非中点）→ 控制律以 12.18 为目标计算偏差。
- 不配置 `TargetMidpoint` → 自动取 `(UpperLimit + LowerLimit) / 2`。

## P1-1 修正 DriftScore 的「拍」定义

**问题**：每来一条新记录就记一拍 slope，但 150 条窗口重叠 99%+，连续 3 拍同号几乎必然，漂移判定形同虚设/误触发。

**修改**：
- `MainViewModel` 维护每个压头「自上一拍以来新增的有效样本数」；仅当新增样本数 ≥ `DriftSampleStride`（新增配置，默认 = `MinSamplesPerEpoch / 2` = 25，至少 10）时才令 `advanceDriftCycle = true`，否则传 false（现有参数已支持只算不记）。
- 文档注释中明确：一「拍」= 一个基本不重叠的子窗口。

**验收**：回放平稳噪声数据 1000 条，不触发 Drift；注入 0.0005 mm/条 的线性漂移，能在越界前触发。

## P1-2 PLC 写入握手完善

**问题**：写值 + 置标志=1 后不读回、不等待 PLC 清零，可能覆盖未处理的指令。

**修改**（`KeyencePlcAdapter.SendAdjustmentAsync`）：
1. 写入前先 `ReadInt16(statusAddress)`：若标志仍为 1（上一条未处理），本次放弃下发，记日志 `[PLC] 跳过：上一条指令未被处理`，返回 false（冷却期机制会在下个周期重试）。
2. 写 float 后回读校验（`ReadFloat(address)`，误差 < 1e-6 视为成功），失败则不置状态标志并返回 false。
3. 置标志=1 后结束；不阻塞等待清零。
4. 修复现有小 bug：状态标志写入失败分支的日志/事件里引用的是 `result.Message`，应为 `statusResult.Message`。
5. `MockPlcAdapter` 同步模拟标志行为（内存变量，写 1 后下次调用前自动清 0），便于回放测试。

## P1-3 时间基准统一

**问题**：`ResetAndRefreshAsync` 用上位机 `DateTime.Now` 过滤 CSV 记录时间，设备与上位机时钟不同步时过滤错数据。

**修改**：重置水位线改用 `_dataProvider.LastDataTimestamp`（数据自身时间轴）：`_resetTimestamp = _dataProvider.LastDataTimestamp ?? DateTime.Now;`（首次无数据时才回退 Now）。P0-2 的按压头冷却时间戳同样只使用数据时间轴。

## 附录 A：当前配置参数参考（settings.json）

```json
{
  "Controller": {
    "UpperLimit": 12.3,
    "LowerLimit": 12.1,
    "UpperTolerance": 0.02,
    "LowerTolerance": 0.02,
    "ControllerGain": 0.5,
    "MaxStepPerAdjust": 0.02,
    "TrimPercentage": 0.05,
    "WindowSize": 150,
    "MinSamplesPerEpoch": 50,
    "DivergenceThreshold": 0.04,
    "DegradedGainFactor": 0.5,
    "DriftConfirmCycles": 3,
    "DriftSlopeThreshold": 0.0001,
    "TargetMidpoint": 12.2
  }
}
```

关键参数说明：
- `WindowSize = 150`：滑动窗口取最近 150 条有效数据
- `MinSamplesPerEpoch = 50`：调整后需要至少 50 条新数据才进入下一轮判定（warmup / 冷却期）
- `TargetMidpoint = 12.2`：目标值（可独立配置，不必等于规格中点）
