# 压接高度自动调整系统 — 内部培训手册

> 本文档描述系统从 CSV 数据读取到 PLC 指令下发的完整闭环流程。
> 适用于 Run-to-Run (R2R) 闭环控制架构。

---

## 1. 系统概述

本系统是一个 **逐拍闭环控制器**：每完成一轮压接（称为"一拍"），系统自动读取最新测量数据，判断压接高度是否偏离目标，如果偏离则计算调整量并发送给 PLC 执行压头位移。

### 1.1 物理布局

```
压接机
├── 铆压#1（压头 A）── 同时压接 产品1 + 产品2
└── 铆压#2（压头 B）── 同时压接 产品3 + 产品4
```

每个压头独立分析、独立调整，互不干扰。

### 1.2 核心目标

- 将压接高度稳定控制在规格中心点附近
- 在过程漂移时及时修正
- 在过程发散（机械异常）时及时报警停机

## 3. 阶段详解 — ①② 数据读取

### 3.1 CSV 文件结构

```
监视目录/
├── 2026-07-15/
│   ├── 001/
│   │   ├── data.csv    ← 每行一条压接记录
│   │   └── ...
│   └── 002/
│       └── data.csv
└── 2026-07-14/
    └── ...
```

### 3.2 每行数据解析

CSV 每行包含 17+ 列，关键字段映射：

| 列索引 | 内容 | 映射到 |
|--------|------|--------|
| 0 | 时间戳 | `CrimpData.Timestamp` |
| 1 | 产品3 结果 | `Product3Result` (true/false) |
| 2 | 产品4 结果 | `Product4Result` |
| 3 | 产品1 结果 | `Product1Result` |
| 4 | 产品2 结果 | `Product2Result` |
| 7 | 产品3 高度 | `Product3Length` (mm) |
| 10 | 产品4 高度 | `Product4Length` (mm) |
| 13 | 产品1 高度 | `Product1Length` (mm) |
| 16 | 产品2 高度 | `Product2Length` (mm) |

### 3.3 有效性判断

一条数据 **同时满足** 以下条件才算有效 (`IsValid = true`)：
- 4 个产品的 Result 字段全部为 `true`
- 4 个产品的 Length 字段全部不等于 `999`

**注意**：只要任一产品无效，整行数据被排除，4 个产品都不参与本轮计算。

### 3.4 数据窗口

系统只取最近 `WindowSize`（默认 200）条有效数据参与计算。数据按时间正序排列。

## 4. 阶段详解 — ③④ 统计计算

### 4.1 截尾均值 (TrimmedMean)

**目的**：消除极端值（飞溅、测量异常）对均值的影响。

**算法**：
1. 将数据从小到大排序
2. 去掉头尾各 `TrimPercentage`（默认 5%）的数据
3. 对剩余数据求平均

**示例**：100 条数据，去掉前 5 条和后 5 条，对中间 90 条求均值。

### 4.2 各层均值的含义

| 均值 | 计算范围 | 用途 |
|------|----------|------|
| 产品1 截尾均值 μ₁ | 仅产品1的数据 | 发散检测输入 |
| 产品2 截尾均值 μ₂ | 仅产品2的数据 | 发散检测输入 |
| 合并截尾均值 μ | 产品1 ∪ 产品2 的全部数据 | 偏差计算、安全检查、调整量计算 |

### 4.3 偏差 (Deviation)

```
TargetMidpoint = (UpperLimit + LowerLimit) / 2
               = (12.65 + 12.55) / 2
               = 12.60 mm

Deviation = μ − TargetMidpoint
```

- `Deviation > 0` → 压接高度偏高（压得太浅）
- `Deviation < 0` → 压接高度偏低（压得太深）

### 4.4 线性回归斜率 (Slope)

对当前窗口数据做最小二乘线性回归，计算斜率：

```
slope = Σ(xi − x̄)(yi − ȳ) / Σ(xi − x̄)²
```

- `slope > 0` → 数据有上升趋势
- `slope < 0` → 数据有下降趋势
- `|slope|` 越大 → 趋势越明显

斜率是漂移检测的核心输入。

## 5. 阶段详解 — ⑤ 五级优先级仲裁（核心）

这是整个系统的决策中枢。每拍每压头执行一次，按优先级从高到低匹配，**命中即止**，产出唯一的 `HeadDecision`。

```
                    ┌──────────────────────┐
                    │   开始仲裁 (Arbitrate) │
                    └──────────┬───────────┘
                               │
                    ┌──────────▼───────────┐
               ┌────┤  P1: 安全护栏触发？    │
               │    │  SafetyGuard.Check()  │
               │    └──────────┬───────────┘
               │ Yes           │ No
        ┌──────▼──────┐  ┌────▼─────────────┐
        │ Outlier      │  │ P2: 样本数 < 50？ │
        │ 停机报警      │  └────┬─────────────┘
        │ Δ = 0        │  Yes  │  No
        └──────────────┘ ┌────▼──────┐  ┌──────────────────────┐
                         │ WarmUp    │  │ P3: 发散等级 = Stop？ │
                         │ 等待数据   │  │ |D| > 2T             │
                         │ Δ = 0     │  └────┬─────────────────┘
                         └───────────┘  Yes  │  No
                                   ┌────────▼──────┐  ┌──────────────────────────┐
                                   │ 停机           │  │ P4: 越界 或 漂移确认？    │
                                   │ DivergenceStop │  │ outOfBounds || drifting  │
                                   │ Δ = 0          │  └────┬─────────────────────┘
                                   └────────────────┘  Yes  │  No
                                              ┌────────────▼────────────┐  ┌──────────┐
                                              │ 计算调整量               │  │ Stable   │
                                              │ Δ = K × Deviation       │  │ 稳定     │
                                              │ 带死区和步长限幅         │  │ Δ = 0    │
                                              └─────────────────────────┘  └──────────┘
```

### 5.1 P1: 安全护栏（最高优先级）

**触发条件**（任一满足即命中）：

| 检查项 | 条件 | 含义 |
|--------|------|------|
| 合理性阈 | μ < 12.40 或 μ > 12.80 | 均值严重偏离，可能是测量错误或模具损坏 |
| σ 突增 | σ > 基线σ × 3.0 | 过程波动突然变大，可能是模具松动 |
| 数据失活 | 最后数据时间距今 > 60s | 数据源中断，无法信任当前判断 |

**产出**：`State = Outlier`，发停机指令，不做任何调整。

### 5.2 P2: 置信不足

**触发条件**：有效样本数 < `MinSamplesPerEpoch`（默认 50）

**场景**：刚换模、刚开机、epoch 刚重置时，数据量不够，统计结果不可信。

**产出**：`State = WarmUp`，不动作，继续采集数据。

### 5.3 P3: 发散严重 (Stop)

**触发条件**：两个产品的截尾均值差异 `|D|` > 2T（T = 0.02mm）

```
D = μ₁ − μ₂
|D| > 0.04mm → Stop
```

**含义**：同一压头下的两个产品高度差异过大，说明机械结构有问题（如模具磨损不均），单靠调整压头位置无法同时修正两个产品。

**产出**：`State = Drift` + `DivergenceLevel = Stop`，发停机指令，需人工维护。

### 5.4 P4: 触发调整（越界 或 漂移确认）

**触发条件**（满足任一）：

#### 条件 A：偏差越界

```
Deviation > UpperTolerance (0.02mm)  → 偏高越界
Deviation < −LowerTolerance (−0.02mm) → 偏低越界
```

死区范围：`[−0.02, +0.02]` mm。偏差在死区内不触发调整。

#### 条件 B：漂移确认 (DriftScore)

连续 N 拍（默认 3 拍）的斜率 **同号** 且 **平均幅度超过门限**。

**两个条件必须同时满足**：

| 条件 | 说明 | 参数 |
|------|------|------|
| 方向一致 | 最近 3 拍的 slope 全部 > 0 或全部 < 0 | `DriftConfirmCycles = 3` |
| 幅度显著 | 最近 3 拍的平均 \|slope\| ≥ 0.0001 mm/拍 | `DriftSlopeThreshold = 0.0001` |

**数据对齐**：漂移检测前，先对两个产品的数据分别减去各自均值，消除产品间固定落差，只关注趋势。

**示例**：

```
Beat 1: slope = +0.00015  ✓ 同向
Beat 2: slope = +0.00020  ✓ 同向
Beat 3: slope = +0.00012  ✓ 同向
平均 |slope| = 0.000157 > 0.0001  ✓ 幅度足够
→ 确认漂移，触发调整
```

```
Beat 1: slope = +0.00015  ✓ 同向
Beat 2: slope = −0.00010  ✗ 方向反转，计数器重置
Beat 3: slope = +0.00020  ✓ 重新开始计数
→ 不确认漂移
```

**产出**：调用 `R2RController.ComputeAdjustment()` 计算调整量。

### 5.5 P5: 稳定

以上条件均不满足 → 系统判定为稳态。

**产出**：`State = Stable`，不动作。

## 6. 阶段详解 — 调整量计算 (R2RController)

当 P4 命中时，进入调整量计算。

### 6.1 计算公式

```
effectiveK = ControllerGain (0.5)
如果 DivergenceLevel == Degraded:
    effectiveK = ControllerGain × DegradedGainFactor = 0.5 × 0.5 = 0.25

Deviation = μ − TargetMidpoint

rawDelta = effectiveK × Deviation

clampedDelta = Clamp(rawDelta, −MaxStepPerAdjust, +MaxStepPerAdjust)
             = Clamp(rawDelta, −0.01, +0.01)
```

### 6.2 死区判断（在公式之前）

如果偏差在死区内，直接返回 0，不进入公式计算：

```
−LowerTolerance ≤ Deviation ≤ UpperTolerance
−0.02 ≤ Deviation ≤ +0.02
→ Δ = 0（不动作）
```

### 6.3 发散等级对调整量的影响

| 发散等级 | K 倍率 | 效果 |
|----------|--------|------|
| Normal | 1.0 × K = 0.5 | 正常调整 |
| Degraded | 0.5 × K = 0.25 | 调整量减半，更保守 |
| Stop | 不计算 | P3 已拦截，停机 |

### 6.4 调整方向

```
Δ > 0 → 压头下降（压得更深，高度降低）
Δ < 0 → 压头上升（压得更浅，高度升高）
Δ = 0 → 不动作
```

### 6.5 计算示例

**场景**：截尾均值 μ = 12.623mm，目标 12.60mm，发散 Normal

```
Deviation = 12.623 − 12.60 = +0.023mm（偏高）
rawDelta  = 0.5 × 0.023 = +0.0115mm
clamped   = Clamp(+0.0115, −0.01, +0.01) = +0.01mm（被限幅）

→ 压头下降 0.01mm
```

**场景**：截尾均值 μ = 12.585mm，目标 12.60mm，发散 Degraded

```
Deviation = 12.585 − 12.60 = −0.015mm（偏低）
effectiveK = 0.5 × 0.5 = 0.25
rawDelta   = 0.25 × (−0.015) = −0.00375mm
clamped    = −0.00375（未触发限幅）

→ 压头上升 0.00375mm（降级模式，调整更保守）
```

## 7. 阶段详解 — 发散检测 (DivergenceGrader)

发散检测衡量同一压头下两个产品的高度差异。

### 7.1 计算

```
D = μ₁ − μ₂（产品1截尾均值 − 产品2截尾均值）
```

### 7.2 三级判定

```
        ┌──────────────────────────────────────────────────┐
        │           |D| 与阈值 T 的关系                      │
        ├──────────┬───────────────────────────────────────┤
        │ |D| < T  │ Normal   — 正常，全速控制               │
        │ T ≤ |D| ≤ 2T │ Degraded — 降级，K 减半，更保守    │
        │ |D| > 2T │ Stop     — 停机，需人工维护             │
        └──────────┴───────────────────────────────────────┘
        T = DivergenceThreshold = 0.02mm（默认）
```

### 7.3 物理含义

- **Normal**：两个产品高度一致，说明模具状态良好
- **Degraded**：两个产品开始出现差异，可能是轻微磨损，降低增益避免过度修正
- **Stop**：两个产品差异过大，单靠调整压头位置无法同时修正，必须停机检查模具

### 7.4 发散与调整的交互

发散等级 **不直接触发调整**，但会 **调制调整量**：

- Normal → 正常 K
- Degraded → K 减半（调整更保守）
- Stop → 不调整，直接停机（在 P3 被拦截）

## 8. 阶段详解 — 漂移检测 (DriftDetector)

漂移检测判断压接高度是否在持续向一个方向偏移。

### 8.1 检测流程

```
每拍执行：
  1. 对当前窗口数据做线性回归，得到 slope
  2. 将 slope 存入历史队列（保留最近 6 个值）
  3. 检查最近 3 个 slope：
     ├─ 全部 > 0？ → 方向一致（上升趋势）
     ├─ 全部 < 0？ → 方向一致（下降趋势）
     └─ 有正有负？ → 方向不一致，不判漂移
  4. 如果方向一致，检查平均幅度：
     └─ 平均 |slope| ≥ 0.0001 mm/拍？ → 确认漂移
```

### 8.2 为什么需要数据对齐？

同一压头下的两个产品可能有固定的测量落差（例如产品1平均比产品2高 0.01mm）。如果不消除这个落差，斜率计算会被产品间的固定差异干扰，导致误判漂移。

**对齐方法**：每个产品数据减去各自均值，只保留波动趋势。

```
对齐前：P1 = [12.61, 12.62, 12.63]  P2 = [12.59, 12.60, 12.61]
对齐后：P1' = [−0.01, 0, +0.01]      P2' = [−0.01, 0, +0.01]
合并后做斜率 → 只反映趋势，不反映产品间落差
```

### 8.3 漂移 vs 越界

| 情况 | 触发方式 | 含义 |
|------|----------|------|
| 越界 | 单拍偏差超出容差 | 突然偏离，可能是阶跃变化 |
| 漂移 | 连续多拍趋势一致 | 渐进偏移，可能是温度漂移、模具磨损 |

两者是 **或** 关系，任一满足即触发调整。

## 9. 阶段详解 — ⑥ PLC 指令下发

### 9.1 指令优先级

```
停机指令 > 调整指令
```

系统先检查两个压头是否需要停机，如果有任一压头需要停机：
1. 发送停机指令
2. **跳过所有调整指令**

只有在两个压头都不需要停机时，才发送调整指令。

### 9.2 判断逻辑

```csharp
if (压头A需要停机)
    → 发送停机(原因A)
else if (压头B需要停机)
    → 发送停机(原因B)
else
    if (压头A需要调整)
        → 发送调整(压头A索引=0, ΔA)
    if (压头B需要调整)
        → 发送调整(压头B索引=1, ΔB)
```

### 9.3 什么情况需要停机？

| 场景 | State | DivergenceLevel | RequiresStop |
|------|-------|-----------------|--------------|
| 安全护栏触发 | Outlier | 任意 | `true` |
| 发散严重 | Drift | Stop | `true` |
| 其他 | 任意 | 非Stop | `false` |

### 9.4 什么情况需要调整？

`State == Drift` 且 `AdjustmentDelta ≠ 0`

即：仲裁命中 P4（越界或漂移确认），且计算出的调整量非零。

### 9.5 PLC 通信接口

```csharp
interface IPlcAdapter
{
    // 发送调整指令
    // headIndex: 0=压头A, 1=压头B
    // deltaMm: 正=下降, 负=上升
    Task SendAdjustmentAsync(int headIndex, double deltaMm);

    // 发送停机指令
    Task SendStopAsync(string reason);

    // 读取压头当前位置
    Task<double?> ReadHeadPositionAsync(int headIndex);
}
```

## 10. 状态机总结

### 10.1 压头状态 (HeadState)

```
     ┌─────────────────────────────────────────────────┐
     │                                                 │
     ▼                                                 │
  WarmUp ──── 样本足够 ────→ Stable                   │
  (数据采集中)               (稳态，不动作)             │
     │                         │                       │
     │                         │ 越界/漂移确认          │
     │                         ▼                       │
     │                       Drift ──── 调整后 ────→ Stable
     │                       (执行调整)                 │
     │                                                 │
     └──── 安全护栏触发 ────→ Outlier                  │
                               (停机报警) ──── 人工修复后重置
```

### 10.2 发散等级 (DivergenceLevel)

```
  Normal ──── |D| 增大 ────→ Degraded ──── |D| 继续增大 ────→ Stop
  (全速控制)                  (K 减半)                          (停机)
```

### 10.3 完整状态转换表

| 当前状态 | 条件 | 下一状态 | 动作 |
|----------|------|----------|------|
| 任意 | 安全护栏触发 | Outlier | 停机 |
| 任意 | 样本不足 | WarmUp | 等待 |
| 任意 | 发散 Stop | Drift(Stop) | 停机 |
| 任意 | 越界或漂移确认 | Drift | 计算调整量并发送 |
| 任意 | 以上均不满足 | Stable | 不动作 |

## 11. 关键参数速查表

### 11.1 规格参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `UpperLimit` | 12.65 mm | 压接高度规格上限 |
| `LowerLimit` | 12.55 mm | 压接高度规格下限 |

## 12. 常见问题 FAQ

**Q1: 为什么用截尾均值而不是普通均值？**
截尾均值去掉头尾极端值后求平均，对飞溅、测量异常等离群点更鲁棒。如果用普通均值，一个异常数据点就可能触发不必要的调整。

**Q2: 为什么漂移检测要对齐数据？**
同一压头下的两个产品可能有固定的高度落差。对齐后只关注"趋势"，不会因为产品间固定差异而误判漂移。

**Q3: 发散 Degraded 为什么不是停机？**
Degraded 说明两个产品有差异但还在可控范围。此时降低增益（K 减半）让调整更保守，同时继续监控。如果差异继续恶化到 Stop 级别才停机。

**Q4: 越界和漂移是什么关系？**
越界是"当前偏差已经超出容差"，漂移是"趋势上正在持续偏离"。两者是"或"关系，任一满足就触发调整。越界处理的是突变，漂移处理的是渐变。

**Q5: 调整量的正负号是什么意思？**
正 Δ = 压头下降（压得更深，高度降低）；负 Δ = 压头上升（压得更浅，高度升高）。系统根据偏差方向自动判断。

**Q6: 两个压头是独立的吗？**
是的。每个压头有独立的 DecisionArbiter 实例，各自维护漂移历史和安全基线，互不干扰。
