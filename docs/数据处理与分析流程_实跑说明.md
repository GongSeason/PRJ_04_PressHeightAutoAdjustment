> 本文对照实际代码（`CsvDataProvider`、`MainViewModel.RefreshDataAsync`、`DecisionArbiter.ArbitrateSingle`、`SafetyGuard`、`DriftDetector`、`R2RController`）整理，
> 并用仓库内真实数据 `rsc/Data_F2_20260928.csv` 跑了一遍，给出每一步的真实中间结果。
> 异常/失活链路本次仅作标注，不展开。

## 二、处理流程总览

每 10 秒一次，两个压头各走一遍下面的流程，互相独立。

### 第 0 步：取数据

1. 在 `rsc` 里选**最新一个** CSV（按文件名日期+修改时间排序）。
2. 从**文件末行向上**读，跳过表头、空行、未写完整的末行，收集最多 `WindowSize=100` 条“数据行”（列数≥7）。
3. 结果反转为**时间正序**返回。记录不足 100 条不回退旧文件。
4. 压头1取第 2 列（`1高度`），压头2取第 4 列（`2高度`）；高度为非有限数或 ≤0 视为**无效**。

> CSV 表头：`Time,1高度,1最大宽度,2高度,2最大宽度,1开口宽度上,2开口宽度上`

**整体判断**：若 100 条里压头全部无效 → 走“无数据”分支（计时、超时请求停机，本文不展开）。只要有有效数据，就进入下面的仲裁。

### 仲裁流程（命中即止，从上往下）

| 顺序 | 条件 | 结果 | 是否下发 |
|---|---|---|---|
| ① | 有效样本 = 0 | **WarmUp** | 不动作 |
| ② | 安全护栏命中（均值超 [12.45,12.8] / σ 突增 3× / 数据失活 >60s） | **Outlier** | 发停机，不发偏移 |
| ③ | 有效样本 < 50 | **WarmUp**（置信不足） | 不动作 |
| ④ | 偏差越界(\|dev\|>0.02) **或** 连续3拍同向且平均\|斜率\|≥0.0001 | **Drift** | 发调整量 Δ |
| ⑤ | 以上都不满足 | **Stable** | 不动作 |

### 调整量计算（仅 Drift）

```
偏差 dev = 截尾均值 - 12.6
死区: dev ∈ [-0.02, +0.02] → Δ = 0
否则: Δ = K(0.5) × dev，再限幅到 ±0.01
正Δ = 压头下降，负Δ = 压头上升
PLC 写入值 = round(Δ × 100000)   # 真实 PLC；Mock 仅写日志
```

### 下发（SendPlcCommandsAsync）

- 任一压头要求停机 → 优先发停机，本次不发调整。
- 否则对判为 Drift 且 Δ≠0 的压头分别下发。
- **去重**：同一数据时间戳 + 同一压头 + 同一 Δ，成功发一次后不重发；新数据（时间戳变化）才再评估。写入失败下一拍可重试。

## 三、真实 CSV 实跑结果

数据源：`rsc/Data_F2_20260928.csv`

- 文件共 573 行，数据行 571 条；压头1、压头2各 505 条高度 >0。
- 前约 33 行高度为 0（开机预热段，无效）。
- 取**最新 100 条数据行**参与本次分析。

| 项目 | 压头1 (H1) | 压头2 (H2) |
|---|---|---|
| 最新100条中有效样本 | 67 | 67 |
| 截尾均值 (trim 5%) | 12.18190 | 12.17354 |
| 偏差 (均值 − 12.6) | **−0.41810** | **−0.42646** |
| 标准差 | 0.18290 | 0.20134 |
| 斜率 (mm/拍) | −0.003789 | −0.004335 |
| min / max | 11.511 / 12.308 | 11.417 / 12.265 |
| 越界 (\|dev\|>0.02) | True | True |
| 判定状态 | **Drift（越界）** | **Drift（越界）** |
| Δ 调整量 (限幅后) | **−0.01000 mm** | **−0.01000 mm** |
| PLC 写入值 (Δ×100000) | **−1000** | **−1000** |
| 方向 | 压头上升 | 压头上升 |

### 逐步推演（以压头1为例）

1. 最新 100 数据行 → 过滤 H1>0 → **67 条有效**。
2. 67 > 0 → 跳过 ①。
3. 截尾均值 12.1819 在 [12.45,12.8] **之外**？12.1819 < 12.45 → **本应触发安全护栏 ②（Outlier）**。见下方“重要提醒”。
4. （若不计安全护栏）67 ≥ 50 → 跳过 ③。
5. 偏差 = 12.1819 − 12.6 = −0.4181，`|dev|=0.4181 > 0.02` → **越界成立 → Drift**。
6. Δ = 0.5 × (−0.4181) = −0.209 → 限幅到 **−0.01**（压头上升）。
7. Mock 模式：日志 `压头A 调整 -0.01000mm`；真实 PLC：向 `D100` 写 **−1000**。

## 四、重要提醒（需你确认）

1. **安全护栏实际会先命中。** 本段截尾均值 12.18 < 安全下限 12.45，按代码优先级 ② 高于 ④，`ArbitrateSingle` 会判 **Outlier → 发停机，Δ=0**，而**不是** Drift 下发 −0.01。
   上表“Drift/−1000”是**在忽略安全护栏时**控制律本身的输出，用于说明调整量算法；真实运行这段数据会停机报警。
   说明这份历史数据整体偏低（min 低到 11.4），不是一段正常稳态数据。

2. **时间戳列是科学计数法** `2.02609E+16`，`ParseTimestamp` 无法解析，会回退用**文件修改时间**。
   影响：漂移“拍”推进和数据失活判断依赖记录时间戳，回退后这两处会用文件时间代替。高度分析不受影响。

3. 当前 `UseRealPlc=false`，联调观察下发值需看 Debug 日志或界面压头卡片“调整量”栏（界面暂无日志面板）。

## 六、正常案例（配置与数据匹配后重跑）

第三节的 Outlier 停机，根因是 `settings.json` 的目标 12.6 与这台设备真实高度（约 12.2）不匹配。
对全文件做整体统计后，按数据反推一套贴合的演示规格重跑，即可看到正常的 Stable / 小幅 Drift 下发行为。

### 全程整体统计（505 条有效样本）

| 项目 | 压头1 (H1) | 压头2 (H2) |
|---|---|---|
| 全程均值 | 12.1931 | 12.1911 |
| 截尾均值 5% | 12.1985 | 12.1988 |
| 标准差 | 0.0698 | 0.0764 |
| min / max | 11.511 / 12.308 | 11.417 / 12.265 |

> 结论：整份数据高度全程稳定在 **≈12.20**，不存在接近 12.6 的区间。
> 原配置目标 12.6、安全下限 12.45 与数据不匹配，才导致全程 Outlier。

### 演示配置（按数据反推）

| 参数 | 值 |
|---|---|
| TargetMidpoint 目标中点 | **12.20** |
| UpperLimit / LowerLimit | 12.25 / 12.15 |
| 容差 UpperTolerance / LowerTolerance | ±0.02 |
| SafetyLowerBound / SafetyUpperBound | 11.9 / 12.5 |
| K / 限幅 / trim | 0.5 / ±0.01 / 5% |

### 最新 100 条实跑结果

| 项目 | 压头1 (H1) | 压头2 (H2) |
|---|---|---|
| 有效样本 | 67 | 67 |
| 截尾均值 | 12.18190 | 12.17354 |

### 两种正常行为对照

- **压头1 → Stable**：偏差 −0.018 落在死区 ±0.02 内 → 判稳定，Δ=0，**不下发**。界面绿色“无需调整”。
- **压头2 → Drift**：偏差 −0.026 刚越过下容差 → 判漂移，Δ=0.5×(−0.026)=−0.013，限幅到 **−0.01**，下发 PLC **−1000**（压头上升）。界面橙色显示方向 + Δ。

> 这同时验证了死区、限幅、Stable/Drift 判定与下发逻辑均正确；第三节的全程 Outlier 纯属配置与数据不匹配，非代码缺陷。

### 需注意

这段 100 条的标准差高达 0.18，远大于全程截尾标准差 0.07，因为末段混入了 11.5 左右的异常低点。
真实投产若想减少误触发，可考虑加大 `TrimPercentage` 或排查异常低点来源。
